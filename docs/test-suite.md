# Workflow suite and replacement coverage

> Realtime architecture update: current GPT-Live coverage is documented in [OpenAI realtime voice](openai-realtime.md). The earlier exact-transcript, PCM playback, truncation, and saved-speech recovery cases below describe the previous implementation and historical CI evidence. Current tests cover direct WebRTC, native client-delegation metadata, immutable timestamped fragments, graceful session finalization, and context continuity.

This suite follows Toolkit's integration and workflow guidance. A case must run a real application operation and reject an incorrect observable result. External protocol fixtures replace providers; Pocket's parsing, decisions, transport, storage and rendering execute normally. There are no isolated unit suites.

## Fixture provenance and isolation

- Codex: `tests/simulators/contracts/codex.json`, `provenance.json` and `calibration.json`, retained from the base commit; CLI **0.163.0-alpha.10.2** schema and prior native calibration. RPC parsing/schema validation runs in the external process. Unsupported methods fail explicitly. Current live compatibility is unverified.
- Claude: retained saved-wire fixtures and `contracts/claude.json`, tied to locked Agent SDK **0.3.303**; application adapter, metadata persistence and read-only projection execute normally. Native Claude Code calibration was not rerun.
- Pi: the documented SDK faux-provider boundary from locked `@earendil-works/pi-ai` **1.4.0**, `dist/providers/faux.d.ts`. Fixed tool/text/error examples drive the real session/tool loop. The fixture rejects unconsumed scripted responses and unexpected inference counts. This verifies Pocket's use of Pi; it does not establish live OpenAI HTTP compatibility.
- Voice: `voice-workflow.ts` uses JSON Live-session creation and loopback sidebands with native transcript, delegation, commentary-acknowledgment, and session-closure envelopes. Browser provider fixtures are explicitly synthetic. Native event and delegation identities bind only declared correlation fields; speech and expected answers are fixed. Dummy credentials are labeled synthetic and no provider account is contacted.
- History: `history/codex-notes.json` is a sanitized contract-shaped documentation example; `history/task-decisions.json` is an authored Decisions scenario with exact candidate/matched inputs. These are not claimed as recordings. Live capture dates are unavailable. Both JSON files are parsed before replay.
- Every Node workflow owns disposable state; the runner supplies an empty PATH, temporary home and no inherited credentials. Browser workers start only their fixture, reject occupied ports, poll `/api/version`, preserve diagnostics per project/worker and stop the owned process group with bounded escalation before removing runtime state. Native replay mismatches are journaled and checked by the owning workflow, so an application-swallowed RPC error cannot hide an unexpected call. Each browser project has a distinct Next build directory. Browser contexts remain independent.

### Pi ingestion regression and correction

```sh
node --import tsx scripts/test-flows.ts tests/workflows/history.test.ts --test-name-pattern='Pi source ingestion archives'
```

Before the fix, this case failed at the live-ingestion assertion: **expected seven active user messages, received zero**, after all seven provider responses and canonical turns completed successfully. That pre-fix result was reproduced on the unchanged production implementation. The assertion remains intact.

The locked SDK publishes `message_end` before synchronously appending ordinary messages, and does not publish `entry_appended` for that path. Pocket previously listened only for `entry_appended`, so startup catch-up could recover the source but live ingestion missed it. `PiTaskContext.sync` now queues a read of the authoritative manager's unprocessed tail after the event listener returns, using the same serialized cursor for message and explicit-entry events. The durable cursor advances through every native entry. The workflow waits on explicit live-ingestion readiness before its exact assertions and shutdown, preserving asynchronous archival during normal turn completion. Native source IDs and original payloads are preserved.

The focused case now passes all stages: seven exact live user messages before shutdown, unchanged membership/revision after resume, consumption of all ten documented Decisions exchanges, closure after five unrelated messages, preserved remaining active messages and public MCP search returning both original archived requests. No model account or paid provider call was used. The actual Pi SDK and QMD/MCP implementation run against the declared external fixtures.

The user authorized the production fix and publication/merge after successful final-head CI. CI results and cache-service evidence are recorded with the PR; local checks alone do not establish full-suite or live-provider compatibility.
