# Pocket edit feedback hooks

The repository hook config runs `scripts/edit-hooks/before-edit.ts` for bookkeeping and `scripts/edit-hooks/after-edit.ts` for feedback. The after-edit runner uses this checkout's Prettier, then ESLint auto-fix and a final ESLint pass. It sends remaining diagnostics as `PostToolUse.additionalContext`. The hooks emit no blocking decisions, and the original tool result remains available. Clean files produce no feedback, even when auto-fixes changed them.

`scripts/edit-hooks/diagnostics.json` stores accumulated counts by ESLint rule ID. Each completed after-edit cycle adds one per remaining message in the final post-auto-fix ESLint results, before the feedback list is deduplicated or limited to 20 lines. The earlier fix pass is not counted; a rule remaining on a later edit counts again. Messages without a rule ID, including parser or runner failures, are omitted. Keys are kept in alphabetical order. Set `shouldRecordEditHookDiagnostics` in `scripts/edit-hooks/config.ts` to `false` to leave the file untouched. The existing worktree runner lock serializes counter updates, and the file is excluded from edit ownership snapshots. Agents commit counter changes with their code; the hook does not stage or commit them.

These hooks require Node 24 or newer and the checkout's development dependencies (`npm ci --include=dev`). Codex CLI 0.163.0 reports `hooks` as a stable enabled feature. Project-local hooks run only after the project `.codex/` layer is trusted and the exact definitions are reviewed and trusted in the CLI's `/hooks` browser. A changed definition requires review again. The config does not enable trust or activate hooks in already running Pocket sessions. [Codex hook documentation](https://learn.chatgpt.com/docs/hooks) describes the native trust and output contracts.

The matchers cover Codex `Bash`, `apply_patch`, and MCP tool names containing common editing verbs. Native tool hooks observe supported tool calls, not arbitrary filesystem writes. `apply_patch` paths and MCP `path`, `file_path`, `filename`, or `target_path` arguments scope attribution to declared files. Other shell and MCP edits use before/after Git-visible content snapshots. The runner includes new untracked files and skips Git-ignored files, symlinks, multiply linked files, and files ignored by Prettier or ESLint. It leaves previously dirty files alone when their content did not change during the tool call.

Concurrent operations with declared, disjoint paths can receive separate feedback. If live operations could own the same path, the runner skips automatic rewrites and says that attribution is ambiguous. Arbitrary concurrent shell writes cannot be attributed exactly from native hook events; their cycles conservatively overlap. A short metadata lock coordinates snapshots and claims; the formatter uses a separate runner lock. The hook checks file digests before rewrites, but it cannot resolve conflicting writes made by separate tools or prevent an external write in the small interval between a digest check and a write. Stale locks are recovered when their owner process is gone. The native `Interrupt` hook marks that main-thread turn and attempts to clear its snapshots, including when interruption overlaps a before-edit snapshot. Codex does not send `Interrupt` for subagents, and a crashed process may skip it. If no tool is active in the checkout, remove orphaned `*.json` and `*.interrupted` files from `$(git rev-parse --absolute-git-dir)/pocket-edit-hooks/` to restore feedback. Feedback shows at most 20 sorted, deduplicated final ESLint diagnostics; run the normal repository checks for the complete list.
